# בדיקת סליקה ב־Sandbox של Morning

**המטרה:** להוכיח מול Morning עצמה (לא מול שרת מדומה) שהסל נגבה בסכום הנכון, שההזמנה מסומנת כשולמה רק אחרי אימות, ושמסמך תקין מופק.
**מה לא נוגע בכסף אמיתי:** הכול רץ ב־Sandbox עם עסק פיקטיבי. הסקריפט `scripts/sandbox-verify.mjs` מסרב לרוץ מול כל כתובת אחרת, ומול `PAYMENT_MODE` אחר מ־`morning_sandbox`.

## הכנה (חד־פעמית)

1. **חשבון Sandbox:** נרשמים לסביבת הבדיקה של Morning, מקימים עסק פיקטיבי, ו„רוכשים” בה את מסלול Best לבדיקה. מפתחות מהחשבון האמיתי **אינם** עובדים כאן.
2. **מפתח API ל־Sandbox:** אזור אישי ← כלים למפתחים ← מפתחות API.
3. **תוסף הסליקה בחשבון ה־Sandbox:** לוודא שאפשר ליצור עמוד תשלום בכרטיס אשראי (קבוצה 100). אם Morning דורשת `pluginId`, למלא ב־`MORNING_PLUGIN_ID`.
4. **כתובת ציבורית ב־https** שמגיעה למחשב שלך, כדי ש־Morning תוכל לשלוח התראות. הפשוט ביותר: `cloudflared tunnel --url http://localhost:8787`.
5. `.dev.vars` (קובץ מקומי שלא נכנס ל־Git; **לא להדביק אותו בצ'אט**):
   ```
   PAYMENT_MODE=morning_sandbox
   ALLOW_LIVE_PAYMENTS=no
   MORNING_AUTH_FLOW=oauth
   MORNING_API_BASE=https://sandbox.d.greeninvoice.co.il/api/v1
   MORNING_AUTH_BASE=https://api.sandbox.morning.dev
   MORNING_GROUP=100
   MORNING_API_KEY_ID=<sandbox id>
   MORNING_API_KEY_SECRET=<sandbox secret>
   PUBLIC_BASE_URL=https://<הכתובת מהמנהרה>
   NOTIFY_SIGNING_SECRET=<מחרוזת אקראית, 32 תווים ומעלה>
   ```

## שלב א׳ — בדיקת הבקשה והחיבור (אוטומטי)

```bash
node scripts/sandbox-verify.mjs form
```

הסקריפט יוצר הזמנה פיקטיבית של שלושה פריטים (₪3,140), שולח בקשה אמיתית ל־Sandbox, ובודק:
אימות, יצירת עמוד תשלום, שסכום הבקשה שווה לסכום שחושב בשרת, ששורות ה־`income` מסתכמות לאותו סכום (כולל מע״מ), שנשלחה קבוצת תשלום, שמספר ההזמנה נמצא ב־`custom` וב־`remarks`, ושכתובת ההתראה חתומה.
בסוף הוא מדפיס כתובת עמוד תשלום ופקודה להמשך.

**ידני:** פותחים את הכתובת, משלמים עם כרטיס הבדיקה שמופיע בתיעוד ה־Sandbox של Morning, ומוודאים שחוזרים לכתובת ההצלחה. אחר כך מעתיקים מלוח הבקרה של ה־Sandbox את מזהה המסמך שנוצר.

```bash
node scripts/sandbox-verify.mjs confirm OY-XXXXXXXX <documentId> --expect-agorot 314000
```

הפקודה מפעילה את אותה פונקציית אימות שהשרת מריץ בהתראה, ובודקת: מסמך מסוג 320, מצב תקין, שמספר ההזמנה בתוכו, מטבע ₪, שורות תשלום אונליין שמסתכמות לסכום המסמך, ושהסכום שווה לסכום ההזמנה בדיוק. היא גם מדפיסה את המסמך כפי ש־Morning החזירה, כדי לתעד הבדלים מהתיעוד.

**כשל נפוץ:** אם הסכום במסמך שונה מהסכום בסל (פער בגובה המע״מ), סימן למע״מ כפול או חסר. לנסות `MORNING_INCOME_VAT_TYPE`, או `MORNING_SEND_INCOME_LINES=false`, ולהריץ שוב. אין לרכך את בדיקת הסכום בקוד.

## שלב ב׳ — מקרי קצה (אוטומטי + ידני)

```bash
node scripts/sandbox-verify.mjs form --decline     # הזמנה של ₪5,600, מעל מגבלת ה־Sandbox
```

התשלום חייב להיכשל. מוודאים שלא נוצר מסמך.

## שלב ג׳ — מהאתר עצמו, מקצה לקצה

```bash
npm run dev          # השרת המקומי, במצב morning_sandbox, מאחורי המנהרה
```

פותחים את כתובת המנהרה ועוברים את כל המסלול כמו לקוח. בכל מקרה לרשום תוצאה בטבלה.

## טבלת תוצאות (למלא)

| # | מקרה | תוצאה צפויה | בפועל | עבר? |
|---|---|---|---|---|
| 1 | `form` | כל הבדיקות PASS, נפתח עמוד תשלום | | |
| 2 | תשלום מאושר + `confirm` | PASS בכל השורות, הסכום זהה, אין מע״מ כפול | | |
| 3 | הצגת המסמך שהופק | שם לקוח, שורות, כמויות, מע״מ, סכום כולל נכונים | | |
| 4 | `form --decline` | התשלום נכשל, אין מסמך | | |
| 5 | **מהאתר:** סל מרובה מוצרים, תשלום מאושר | בסיום ההזמנה `paid` ושובר מוצג, מסומן „לדוגמה” | | |
| 6 | **מהאתר:** ביטול בעמוד התשלום | חזרה לאתר, ההזמנה `cancelled`, הסל נשמר | | |
| 7 | **מהאתר:** חזרה מעמוד התשלום לדף ההצלחה בלי לשלם | ההזמנה נשארת `awaiting_payment`, אין שובר | | |
| 8 | התראה אמיתית מגיעה | נשמרת ב־`payment_events` (מבנה הגוף מתועד), ההזמנה `paid` רק אחרי הקריאה בחזרה | | |
| 9 | התראה כפולה (ראו למטה) | לא משנה דבר, לא מייצרת מסמך שני | | |
| 10 | התראה עם חתימה שגויה | 403 | | |
| 11 | רענון בזמן המתנה לתשלום | המצב נשמר ואין הזמנה נוספת | | |
| 12 | אזור הניהול על ההזמנה הזו (Access מוגדר) | נראית כ־Sandbox, לא נספרת בהכנסות האמיתיות | | |

**בדיקת התראה כפולה (9):** מעתיקים את גוף ההתראה האחרון מהמסד ושולחים אותו שוב לאותה כתובת:
```bash
npx wrangler d1 execute oyaku-founders-orders --local --command "SELECT order_id, outcome, payload FROM payment_events ORDER BY id DESC LIMIT 1"
SIG=$(node -e "console.log(require('crypto').createHmac('sha256', process.argv[1]).update(process.argv[2]).digest('hex'))" "<NOTIFY_SIGNING_SECRET>" "<orderId>")
curl -s -X POST "https://<מנהרה>/api/morning/notify?order=<orderId>&sig=$SIG" -d '<הגוף שהועתק>'
```
התשובה חייבת להיות `{"ok":true,"duplicate":true}`.

## אם משהו לא תואם

אל תשנו את בדיקות האימות כדי שיעברו. מתעדים את ההבדל כאן ומתקנים את ההגדרה (`MORNING_*`) או שמעבירים אלי את הפלט של `confirm` ושל `payment_events.payload`, ונתאים את המתאם בכוונה.
